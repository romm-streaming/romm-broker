---
title: "Emulator settings"
description: "The environment variables each launcher reads, grouped by emulator. Paths default to where the emulator keeps its data inside the container."
---

Each emulator reads its settings once, when the broker starts up. Every path
below defaults to wherever that emulator normally keeps its own data inside
the container. `HOME` is set to `/config`, and the broker also sets
`XDG_CONFIG_HOME` and `XDG_DATA_HOME` (the standard Linux folders for an
app's settings and data) for the emulators that actually use them. That means
you shouldn't need to change any of these unless you've altered how the
container's folders are laid out. All the timing values in the tables below
are in seconds.

## Shared

| Env var | Default | Purpose |
| --- | --- | --- |
| `XDOTOOL_BIN` | `xdotool` | The xdotool used to send save/load hotkeys to Dolphin and PPSSPP. |
| `XDG_RUNTIME_DIR` | `/config/.XDG` | Where PCSX2's PINE socket (`pcsx2.sock`) is looked for. |
| `DESKTOP_BIN` | `selkies-desktop` | What the `desktop` type launches. |
| `DESKTOP_STOP_WAIT` | `15` | SIGTERM grace before SIGKILL for the desktop session, and for every app left open on it. Longer than the base 5 s because it is mostly spent on those apps writing their config and save data on the way out. |

## PCSX2

| Env var | Default | Purpose |
| --- | --- | --- |
| `PCSX2_BIN` | `pcsx2-qt` | PCSX2 binary. |
| `PCSX2_STATE_SLOT` | `10` | The slot PCSX2 works in; 10 is its own autosave slot, which the per-emulator broker also used. |
| `PCSX2_SLOT1_CARD` | `romm-slot1` | Name of the Slot 1 folder memory card the broker owns (a directory, no `.ps2` extension). |
| `PCSX2_LOG_PATH` | `/config/pcsx2-qt.log` | Where PCSX2's stdout/stderr is captured. |
| `PCSX2_PATCHES_FETCH` | `true` | Fetch PCSX2's game-patch bundle (`patches.zip`) from `PCSX2/pcsx2_patches` before a launch. Set `false` with no route to GitHub. |
| `PINE_WAIT` | `20.0` | How long a save state has to land on disk after the PINE save command. |
| `RESUME_LOAD_WAIT` | `90.0` | How long a resume load waits for PCSX2 to report a running game. |
| `RESUME_LOAD_SETTLE` | `3.0` | How long the game has to be running before the resume load fires. |

PCSX2's data folder isn't configurable here. Everything (`inis/PCSX2.ini`,
`sstates/`, `memcards/`) lives under `/config/.config/PCSX2`.

The Ubuntu PCSX2 package ships without `patches.zip`, the bundle of
widescreen and compatibility patches PCSX2 applies per game, and PCSX2 only
reads it from `/usr/share/PCSX2/resources/`. Before each launch the broker
downloads it from the `latest` release of `PCSX2/pcsx2_patches` when it is
missing, invalid, or older than a week, checks the download is a valid zip of
`.pnach` patches, and moves it into place with `sudo`. A missing or invalid
bundle is fetched before the game starts, which can hold a launch for up to
about a minute; a week-old one is refreshed in the background. A failed
fetch is logged and the game boots with whatever bundle is there, or none.

## Dolphin

| Env var | Default | Purpose |
| --- | --- | --- |
| `DOLPHIN_BIN` | `dolphin-emu` | Dolphin binary. |
| `DOLPHIN_LOG_PATH` | `/config/dolphin.log` | Where Dolphin's stdout/stderr is captured. |
| `DOLPHIN_STATE_SLOT` | `1` | The slot Dolphin works in (Shift+F`n` saves it, F`n` loads it). |
| `DOLPHIN_STATE_WAIT` | `20.0` | How long a save state has to land on disk after the save hotkey. |
| `DOLPHIN_RESUME_LOAD_WAIT` | `90.0` | How long a resume load waits for the render window. |
| `DOLPHIN_RESUME_LOAD_SETTLE` | `5.0` | How long the window has to be up before the load hotkey is sent. |

Dolphin's folders aren't configurable here either. Config (`GCPadNew.ini` and
the rest) lives under `/config/.config/dolphin-emu`, and save data
(`StateSaves/`, `GC/`, `Wii/`) lives under `/config/.local/share/dolphin-emu`.
A desktop session opens Dolphin using these same folders, so if you rebind a
controller there, that change also applies to broker-launched games.

## Cemu

| Env var | Default | Purpose |
| --- | --- | --- |
| `CEMU_BIN` | `Cemu` | Cemu binary. |
| `CEMU_MLC_DIR` | `$XDG_DATA_HOME/Cemu/mlc01` | The mlc01 tree saves are dumped from, passed to Cemu as `-m` on every launch. |
| `CEMU_LOG_PATH` | `/config/cemu.log` | Where Cemu's stdout/stderr is captured. |
| `CEMU_PAD_NAME` | `Microsoft X-Box 360 pad` | The selkies virtual pad's name as the kernel xpad driver presents it, used to derive the SDL GUIDs the controller profile binds. |
| `CEMU_PAD_UUIDS` | unset | Comma separated `<index>_<guid>` list to bind instead of the derived ones. |
| `CEMU_STOP_WAIT` | `5` | SIGTERM grace before SIGKILL (Cemu has no SIGTERM handler, so this only covers process-group teardown). |

Cemu's config folder isn't configurable here. It's `/config/.config/Cemu`. If
you want to move Cemu's save data instead, use `CEMU_MLC_DIR` above: that one
does get passed to Cemu directly, so both sides actually use it.

## shadPS4

| Env var | Default | Purpose |
| --- | --- | --- |
| `SHADPS4_BIN` | unset | Explicit shadPS4 binary; skips the version search. |
| `SHADPS4_VERSIONS_DIR` | `/config/.local/share/shadPS4QtLauncher/versions` | Where the Qt launcher downloads builds, one folder per release; `Pre-release/` trumps the newest semver folder. |
| `SHADPS4_BIN_NAME` | `Shadps4-sdl.AppImage` | The binary looked for inside each version folder. |
| `SHADPS4_LOG_PATH` | `/config/shadps4.log` | Where shadPS4's stdout/stderr is captured. |
| `SHADPS4_STOP_WAIT` | `20` | How long the IPC STOP gets to finish before SIGTERM. |
| `SHADPS4_PKG_EXTRACTOR_BIN` | `pkg_extractor` | The standalone `pkg_extractor` binary a `.pkg` ROM (or a `.7z`/`.zip`/`.rar` archive holding one) is unpacked with; requires `unrar` and `7z` on PATH too when the ROM is an archive. |
| `SHADPS4_PKG_EXTRACT_TIMEOUT` | `1800` | Seconds a `pkg_extractor` (or archive extraction) run gets before it is considered hung. |
| `SHADPS4_CACHE_ENABLED` | `false` | Whether `.pkg` and `.7z`/`.zip`/`.rar` ROMs boot at all. On, the first launch extracts one into `SHADPS4_CACHE_DIR` and every later launch reuses that extraction. Off, such a ROM is refused outright rather than re-extracted and thrown away on every launch; only natively bootable formats work. |
| `SHADPS4_CACHE_DIR` | `$XDG_DATA_HOME/shadPS4/extracted` | Where a kept extraction is cached, when `SHADPS4_CACHE_ENABLED` is on. Broker-owned scratch, written and read by the broker alone, so moving it moves the whole of it. |
| `SHADPS4_CACHE_MAX_GB` | `30` | Ceiling on the cache's total size; the oldest extraction is evicted first once a new one would exceed it. A ROM that still doesn't fit once there is nothing left to evict, or that exceeds the free space on the filesystem, is refused at activate rather than extracted until the disk fills. |
| `SHADPS4_GPU_ID` | `auto` | Which Vulkan device shadPS4 renders on. shadPS4's own `-1` auto-select can land on a software rasterizer, which renders a black screen while the game otherwise runs. `auto` detects the best real GPU; an integer pins that device index directly; `-1` or `KEEP` leaves `config.json` alone. |
| `SHADPS4_VULKANINFO_BIN` | `vulkaninfo` | The binary `SHADPS4_GPU_ID=auto` enumerates devices with. If it is missing or fails, no pin is written and shadPS4 keeps its own setting. |

shadPS4's data folder isn't configurable here. It's
`/config/.local/share/shadPS4`. `config.json` (where the GPU pin above gets
written) sits at the root of that folder, and saves live under
`home/1000/savedata/` inside it.

## RetroArch

| Env var | Default | Purpose |
| --- | --- | --- |
| `RETROARCH_BIN` | `retroarch` | RetroArch binary. |
| `RETROARCH_CONFIG_DIR` | RetroArch's own search order: `$XDG_CONFIG_HOME/retroarch`, else `$HOME/.config/retroarch`, else the legacy `$HOME/.retroarch.cfg` | Where the user's `retroarch.cfg` lives. Passed to RetroArch as `--config` on every launch, so moving it moves the file both read. |
| `RETROARCH_CORES_DIR` | `libretro_directory` from `retroarch.cfg`, else `cores` under RetroArch's own root (`/config/.config/retroarch/cores`) | Where cores are loaded from and downloaded into. That default is also RetroArch's `libretro_info_path`, and a core whose `.info` file is not beside it loads without core info. |
| `RETROARCH_SYSTEM_DIR` | `system_directory` from `retroarch.cfg`, else `system` under RetroArch's own root (`/config/.config/retroarch/system`) | Where cores look for BIOS files and firmware. Written into the `broker.cfg` overlay as `system_directory` on every launch, so moving it moves the directory both use. |
| `RETROARCH_CORES_BASE_URL` | `https://buildbot.libretro.com/nightly/linux/x86_64/latest` | Where missing cores are downloaded from. |
| `RETROARCH_CORE_URL_<CORE>` | unset | Pins one core's download URL without editing `retroarch_platforms.json`. |
| `GITHUB_API_BASE` | `https://api.github.com` | API base for cores whose platform entry names a GitHub release source. |
| `GITHUB_TOKEN` | unset | Bearer token for those GitHub release lookups. |
| `RETROARCH_CORE_DOWNLOAD_TIMEOUT` | `180` | Timeout on a core download. |
| `RETROARCH_DATA_DIR` | `/config/.retroarch` | Broker-managed `states/`, `saves/` and the `broker.cfg` layered on with `--appendconfig`. |
| `RETROARCH_LOG_PATH` | `/config/retroarch.log` | Where RetroArch's stdout/stderr is captured. |
| `RETROARCH_JOYPAD_DRIVER` | `linuxraw` | Joypad driver forced at launch; the udev driver sees the selkies pads as one device plugged eight times. Set empty to leave the user's own driver alone. |
| `RETROARCH_STATE_SLOT` | `0` | The slot RetroArch works in; 0 is its default, so the player's own load hotkey reaches the same file. |
| `RETROARCH_SLOT_STEP_DELAY` | `0.1` | Pause between slot presses while parking the slot. |
| `RETROARCH_SLOT_HOME_STEPS` | `24` | Slot-down presses to reach the -1 floor from anywhere the player could have cycled to. |
| `RETROARCH_STATE_CONFIRM_WAIT` | `10.0` | How long a save state has to land on disk after `SAVE_STATE_SLOT`. |
| `RETROARCH_LOAD_ACK_WAIT` | `10.0` | How long `LOAD_STATE_SLOT` has to be acknowledged. |
| `RETROARCH_RESUME_WAIT` | `90.0` | How long a resume load waits for the core to report a running game. |
| `RETROARCH_RESUME_SETTLE` | `3.0` | How long the game has to be running before the resume load fires. |
| `RETROARCH_SAVE_FILES_WAIT` | `10.0` | How long `SAVE_FILES` (flush SRAM to disk) has to answer at exit. |
| `RETROARCH_QUIT_WAIT` | `10.0` | How long `QUIT` gets to finish before SIGTERM. |
| `RETROARCH_QUIT_CONFIRM_GAP` | `0.1` | Gap before the second `QUIT`, for configs that ask for confirmation. |
| `RETROARCH_DISC_TRAY_SETTLE` | `1.5` | Pause after opening the tray before changing the disc index; an index change during the open is silently dropped. |
| `RETROARCH_DISC_STEP_DELAY` | `0.1` | Pause between disc index presses. |
| `RETROARCH_DISC_SWAP_WAIT` | `90.0` | How long a swap waits for the core to report a running game. |
| `RETROARCH_STOP_WAIT` | `15` | SIGTERM grace before SIGKILL once `QUIT` has been tried. |

## RPCS3

| Env var | Default | Purpose |
| --- | --- | --- |
| `RPCS3_BIN` | `/opt/rpcs3/AppRun` | RPCS3 binary. |
| `RPCS3_LOG_PATH` | `/config/rpcs3.log` | Where RPCS3's stdout/stderr is captured. |
| `RPCS3_INSTALL_TIMEOUT` | `1800` | How long a PKG install may run; decryption of a multi-GB package takes minutes. |
| `RPCS3_BOOT_WAIT` | `90.0` | How long the boot watchdog waits for PINE to report a running game before the launch is flagged `boot_failed`. |
| `RPCS3_STATE_WAIT` | `60.0` | How long the exit-time save-state hotkey has to finish writing before the broker gives up on it; a full state (compressed RAM and VRAM) is a heavier write than the other cores' states. |
| `RPCS3_SAVE_STATE_KEY` | `ctrl+alt+1` | The save-state hotkey sent to trigger an exit-time save. RPCS3's four save-state shortcuts are equivalent and this one is GUI-rebindable, hence configurable here too. |
| `RPCS3_CACHE_ENABLED` | `false` | Whether `.7z`/`.zip`/`.rar` ROMs boot at all. On, the first launch extracts one into `RPCS3_CACHE_DIR` and every later launch reuses that extraction. Off, an archive ROM is refused outright rather than re-extracted and thrown away on every launch. `.pkg` is unaffected either way: it always installs through its own always-on installer. |
| `RPCS3_CACHE_DIR` | `$XDG_CONFIG_HOME/rpcs3/extracted` | Where a kept extraction is cached, when `RPCS3_CACHE_ENABLED` is on. Broker-owned scratch, written and read by the broker alone, so moving it moves the whole of it. |
| `RPCS3_CACHE_MAX_GB` | `30` | Ceiling on the cache's total size; the oldest extraction is evicted first once a new one would exceed it. An archive that still doesn't fit once there is nothing left to evict, or that exceeds the free space on the filesystem, is refused at activate rather than extracted until the disk fills. |
| `RPCS3_STOP_WAIT` | `2` | SIGTERM grace before SIGKILL (no SIGTERM handler, covers the AppImage wrapper teardown). |

RPCS3's data folder isn't configurable here either. On Linux, everything
(`config.yml`, `dev_flash/`, `dev_hdd0/` and the save states) lives under
`/config/.config/rpcs3`.

## ScummVM

| Env var | Default | Purpose |
| --- | --- | --- |
| `SCUMMVM_BIN` | probed | ScummVM binary; `/usr/games/scummvm`, `/usr/bin/scummvm` and `/usr/local/bin/scummvm` are tried in that order. |
| `SCUMMVM_CONFIG_DIR` | `/config/.config/scummvm` | Holds `scummvm.ini`, which the broker pins its settings into and reads game targets back out of. Its `scummvm.ini` is passed as `--config` on every launch and on every `--add`, so moving it moves the file both read. |
| `SCUMMVM_DATA_DIR` | `/config/.local/share/scummvm` | ScummVM's data directory; `saves/` under it is the save subtree and the working slot alike. |
| `SCUMMVM_LOG_PATH` | `/config/scummvm.log` | Where ScummVM's stdout/stderr is captured. |
| `SCUMMVM_STATE_SLOT` | `1` | The slot the broker saves into. Kept low because the chooser is walked one `Down` per slot, and slot 0 is ScummVM's write-protected autosave. |
| `SCUMMVM_MENU_KEY` | `F11` | Key the broker binds to the global menu action in `scummvm.ini`, and opens the Global Main Menu with. ScummVM's own `C+F5` loses its modifier on the way through Xwayland, and the unmodified `F5` belongs to the engine keymap, which an engine may take for itself. |
| `SCUMMVM_STATE_WAIT` | `10` | How long a save waits for the slot's file to change before reporting failure. The menu macro gives no acknowledgement of its own. |
| `SCUMMVM_KEY_DELAY` | `0.8` | Seconds between the macro's steps. The menu and its chooser animate in, and a keystroke sent into either transition is dropped. |
| `SCUMMVM_ADD_TIMEOUT` | `120` | How long `scummvm --add` gets to scan a folder. Detection reads through every file in it. |
| `SCUMMVM_RESUME_LOAD_WAIT` | `45` | How long a deferred resume waits for the parent to push its state. |
| `SCUMMVM_RESUME_LOAD_SETTLE` | `8` | How long that resume then gives the game to reach a state where it answers the menu. |
| `SCUMMVM_FILL_SCREEN` | `true` | Grow the game window to the display after launch, so a 640x480 game is not a postage stamp on a 1080p stream. Done through the window manager, not ScummVM's own fullscreen, which would make SDL grab and confine the pointer against a stack that feeds it absolutely. Best-effort: a failure leaves the game at its own size. |
| `SCUMMVM_FILL_SCREEN_WAIT` | `10` | Seconds to wait for the game window to appear before giving up on growing it. |
| `SCUMMVM_STOP_WAIT` | `10` | Seconds SIGTERM gets, which ScummVM spends flushing its config, before escalating to SIGKILL. |
