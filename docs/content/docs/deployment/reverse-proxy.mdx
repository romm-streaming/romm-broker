The room UI shows the selkies stream in an iframe (a webpage embedded inside
another webpage), and RomM embeds the whole room the same way. When that outer
iframe is cross origin, meaning it comes from a different address than RomM
itself, the browser stops passing mouse movement through to the page around it
the moment the cursor enters the frame. RomM's player can no longer see the
mouse at all, so it has to overlay a strip of its own along the bottom edge to
show its control bar, and that strip sits on top of the container's own
taskbar.

Serving the container from a subfolder of RomM's own origin fixes this: the
player can track the mouse inside the frame, nothing overlays the stream, and
the whole container desktop becomes clickable.

<Callout type="warn" title="Skipping this also breaks the room's camera, microphone and invite-link copy button, not just pointer tracking.">
On the cross-origin path (a full URL in `host`, not a subfolder), three things
fail with no error message pointing back here:

- **Camera and microphone** are refused instantly. `getUserMedia`, the
  browser's built-in API for requesting camera or microphone access, fails
  before the browser ever shows a permission prompt.
- **The invite buttons** can't copy the link automatically and fall back to
  a manual copy prompt instead.
- **Pointer tracking** is lost inside the frame, which is what the edge-strip
  overlay above works around.

All three have the same root cause, and there is no proxy-side fix: the
browser's Permissions-Policy (a built-in browser rule controlling which
permissions a page can hand to the frames inside it) defaults to same-origin
only for camera, microphone, and clipboard-write, and RomM's iframe cannot
grant those permissions to a frame from a different origin.
Websocket forwarding, exploit blocking, and every other proxy setting are
irrelevant here. This is the browser treating the room as a different site,
full stop.

Serving the container from a subfolder of RomM's own origin, below, is the
only fix, and it removes the restriction entirely.
</Callout>

RomM does not proxy any of this itself. A reverse proxy sitting in front of
both services maps a path on RomM's origin to the container. The container is
already built to run behind one.

## The contract

Three rules. Skip any one of them and the setup breaks.

<Callout type="info" title="SUBFOLDER must equal the mount path exactly, trailing slash included.">
The app writes its own file links (like `/streaming/assets/...`) as absolute
paths, and builds its websocket address (the live connection the stream and
room chat run over) from the browser's current address plus that same prefix.
Set `SUBFOLDER` and your proxy's mount path to the exact same value, and
everything lines up automatically. Nothing needs rewriting.
</Callout>

<Callout type="warn" title="The proxy must pass the prefix through, not strip it.">
This is the rule that trips people up most. Most reverse proxies offer a
strip-prefix mode, and several turn it on by default. Strip the prefix here,
and the page will load, then every asset it asks for comes back as a 404 (a
"not found" error) instead.
</Callout>

<Callout type="warn" title="The proxy must forward websocket upgrades.">
The stream, the collab room, and the input channel are all websockets. Without
the upgrade headers the room loads and then sits there dead.
</Callout>

## Container side

```
SUBFOLDER=/streaming/
```

That is the whole container-side configuration. Inside the container, its own
nginx (a small web server) serves the room UI, the broker API, and the selkies
stream, all under that one prefix, so a single proxy rule covers all three.
Port 3000 serves plain HTTP, and port 3001 serves HTTPS with a self-signed
certificate, one your browser or `curl` won't trust automatically, since the
container issued it itself rather than a recognized authority. If your reverse
proxy already handles HTTPS for you (often called TLS termination), point it
at port 3000 instead and skip the warning that certificate would otherwise
trigger.

## RomM side

In RomM's `config.yml`, a streaming container entry uses three keys for this:

```yaml
streaming:
  containers:
    - platform: ps2
      # Where the browser goes. A path means "reverse proxied onto RomM's own
      # origin", and the browser resolves it against whatever origin it is on.
      host: /streaming
      # Where RomM's backend goes, server to server. Required when host is a
      # path, since a path carries no address RomM could call.
      broker_host: http://10.0.1.56:3009
      # The container's SUBFOLDER. RomM builds broker API paths under it.
      subfolder: /streaming
      broker_secret: "..."
      protocol: webstation
      emulator: pcsx2
      library_path: /romm
      label: WEBSTATION
```

`host` can also be a full URL. What matters is the origin it names, not
whether it is written as a path:

- **A full URL on RomM's own origin** (`https://romm.example.com/streaming`,
  where RomM itself is served from `https://romm.example.com`) is the same
  deployment as the path form. The browser ends up at the same address
  either way, so everything on this page applies unchanged. The path in it
  still has to match `subfolder`.
- **A full URL on any other origin** (`https://webstation.example.com`, or
  the same host on a different port or scheme) is the cross-origin
  deployment. RomM's player falls back to its edge-strip overlay
  automatically to make up for the lost pointer tracking, but camera,
  microphone, and automatic invite-link copying stay broken there for the
  reason above. There is no proxy-side fix for those.

`broker_secret` has to match the container's `BROKER_SECRET`. If you would
rather keep it out of `config.yml`, set `STREAMING_BROKER_SECRET` in RomM's
own environment instead. When that is set, RomM uses it for every streaming
container and ignores each entry's `broker_secret`, so it only suits
deployments where all containers share one secret.

### When RomM and the container share a Docker network

If both run from the same Compose file, or are otherwise attached to a
common Docker network, RomM's backend can reach the container by its service
name. Point `broker_host` at that name and the container's own port `3000`,
not a port you published on the host:

```yaml
broker_host: http://romm_webstation:3000
```

A published host port (`3009:3000`) is only reachable through the host's
address, which a container on a bridge network often can't see. Once a
reverse proxy and `broker_host` both reach the container over the Docker
network, it needs no published ports at all.

Session identity is derived from `broker_host`, not `host`, so moving a
container behind a proxy does not disturb a session it is already holding.

## Proxy recipes

<Tabs items={['nginx', 'Nginx Proxy Manager', 'Caddy', 'Traefik']}>
<Tab value="nginx">

```nginx
location /streaming/ {
    proxy_pass http://10.0.1.56:3009;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

`proxy_pass` deliberately has no path after the address. Adding even a bare
`/` makes nginx strip `/streaming/` before forwarding the request, which
breaks every asset the page tries to load. `proxy_buffering off` matters for
the video stream, and the long read timeout keeps an idle session's websocket
connection from being closed while a game is still running.

</Tab>
<Tab value="Nginx Proxy Manager">

<Callout type="warn" title="Add a Custom Location on RomM's own Proxy Host. Do not create a second Proxy Host for the container.">
A separate Proxy Host means a separate domain or subdomain, which is a
cross-origin embed and brings back everything this page exists to avoid
(pointer tracking, camera/mic, clipboard). The container has to end up on a
*path* under the same Proxy Host RomM is already served from.
</Callout>

Open the Proxy Host for RomM's own domain and, under **Custom Locations** at
the bottom of its Details tab, add one:

- **Location**: `/streaming/`. Same rule as everywhere else on this page: it
  has to match `SUBFOLDER` exactly, trailing slash included.
- **Scheme**: `http`
- **Forward Hostname/IP**: the container's address, e.g. `10.0.1.56`
- **Forward Port**: `3009` (or whatever host port maps to the container's 3000)

Custom Locations send traffic straight to that host and port with no path
added in front, so the prefix isn't stripped by default. NPM already gets
that part right.

Click the location's own edit (pencil) icon and paste the rest into its
**Advanced** config box, since the location-level form has no fields for it:

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_set_header Host $host;
proxy_buffering off;
proxy_read_timeout 3600s;
```

The Proxy Host's own **Websockets Support** toggle applies to the whole vhost
(short for virtual host: everything grouped under that Proxy Host), but paste
the upgrade headers into the location's Advanced box anyway. Custom Locations
don't reliably inherit that setting. Leave **Block Common Exploits** on if
you already use it. It only screens query strings for exploit patterns and
has no effect on anything described here.

</Tab>
<Tab value="Caddy">

```txt title="Caddyfile"
handle /streaming/* {
    reverse_proxy 10.0.1.56:3009
}
```

Use `handle`, never `handle_path`. `handle_path` strips the matched prefix,
the same problem as with nginx above. Caddy forwards websocket upgrades on
its own, so there is nothing to add for those.

</Tab>
<Tab value="Traefik">

With Traefik's Docker provider, both routers are labels on the services
themselves. This example assumes RomM and the container sit in one Compose
file, sharing a private `romm-internal` network and joined to an external
`traefik-ingress` network that Traefik also lives on.

```yaml title="docker-compose.yml"
services:
  romm:
    # ...image, volumes and the rest of RomM's own settings
    environment:
      - STREAMING_BROKER_SECRET=change-me
    labels:
      traefik.enable: "true"
      traefik.docker.network: traefik-ingress
      traefik.http.routers.romm.rule: Host(`romm.example.com`)
      traefik.http.routers.romm.entrypoints: websecure
      traefik.http.routers.romm.priority: "1"
      traefik.http.services.romm.loadbalancer.server.port: "8080"
    networks:
      - romm-internal
      - traefik-ingress

  romm_webstation:
    # ...image, volumes and the rest of the container's settings
    environment:
      - SUBFOLDER=/streaming/
      - BROKER_SECRET=change-me
    labels:
      traefik.enable: "true"
      traefik.docker.network: traefik-ingress
      traefik.http.routers.romm_webstation.rule: Host(`romm.example.com`) && PathPrefix(`/streaming/`)
      traefik.http.routers.romm_webstation.entrypoints: websecure
      traefik.http.routers.romm_webstation.priority: "10"
      traefik.http.services.romm_webstation.loadbalancer.server.port: "3000"
    networks:
      - romm-internal
      - traefik-ingress

networks:
  romm-internal:
  traefik-ingress:
    external: true
```

```yaml title="config.yml"
streaming:
  enabled: true
  containers:
    - platform: ps2
      # Either form works, since both name RomM's own origin:
      host: /streaming
      # host: https://romm.example.com/streaming
      broker_host: http://romm_webstation:3000
      subfolder: /streaming
      protocol: webstation
      emulator: pcsx2
      library_path: /romm
```

What each piece is for:

- **Priorities.** Both routers match ``Host(`romm.example.com`)``, and
  RomM's matches every path on it. The explicit `priority` values make sure
  `/streaming/` always goes to the container instead of RomM, rather than
  relying on Traefik's default of ranking rules by their length.
- **`traefik.docker.network`.** Each service is on two networks, so Traefik
  has two addresses to choose from. Naming the network it shares with them
  stops it from picking the `romm-internal` address, which it can't reach,
  and answering with an intermittent `502`.
- **``PathPrefix(`/streaming/`)`` with the trailing slash.** Without it the
  rule also matches `/streaming-2/` and anything else that starts with the
  same letters, which matters as soon as you run [more than one
  container](#running-more-than-one-container).
- **No `stripPrefix` middleware.** The container expects the prefix intact.
- **`broker_host` uses the service name**, as described
  [above](#when-romm-and-the-container-share-a-docker-network). RomM's
  backend talks to the container directly over `romm-internal` and never goes
  through Traefik. The browser is the only thing that uses `host`.
- **`STREAMING_BROKER_SECRET` on RomM** takes the place of `broker_secret` in
  `config.yml`, and must equal the container's `BROKER_SECRET`.

Neither service needs a `ports:` mapping for any of this. Keep one only if
you also want to reach a service directly, bypassing Traefik.

Thanks to [@hylandpad](https://github.com/hylandpad) for the working setup
this recipe is based on ([#66](https://github.com/romm-streaming/romm-broker/issues/66)).

</Tab>

## Verifying

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://romm.example.com/streaming/
```

Expect `200` (the standard "it worked" response). Keep the trailing slash:
the container's nginx answers a bare `/streaming` with a `301` redirect
("moved here instead") to `http://<host>:3000/streaming/`. That redirect
carries the container's own internal port, which is not reachable from
wherever the browser is. Every URL handed to a browser should already end in
the slash, so nothing has to follow that redirect.

Then fetch the page body and confirm the asset paths it references
still carry the prefix:

```bash
curl -sS https://romm.example.com/streaming/ | grep -o 'src="[^"]*"'
```

Every `src` should start with `/streaming/`. If they start with `/` alone, the
container's `SUBFOLDER` is not set. If they look right but return 404 when
fetched, the proxy is stripping the prefix.

Last, confirm the broker answers through the same rule:

```bash
curl -sS https://romm.example.com/streaming/api/health
```

## Running more than one container

The mount path is set per container. The app builds its prefix into every
asset URL when it starts up, so there is no wildcard shortcut and no way to
share one rule across a pool. Each container needs its own `SUBFOLDER`
(`/streaming/`, `/streaming-2/`), its own proxy rule, and its own `config.yml`
entry. Copy the proxy recipe you used above and change both paths in it.

```yaml
streaming:
  containers:
    - platform: ps2
      host: /streaming
      subfolder: /streaming
      broker_host: http://10.0.1.56:3009
      # ...remaining keys as above
    - platform: ps2
      host: /streaming-2
      subfolder: /streaming-2
      broker_host: http://10.0.1.57:3009
      # ...remaining keys as above
```

<Callout type="warn" title="host and subfolder both have to be the container's own SUBFOLDER.">
`host` and `subfolder` are not independent settings. The browser is sent to
`host`, but the broker answers the claim with a room URL built from its own
`SUBFOLDER`, and that is an absolute path, so it replaces whatever path `host`
was carrying. A container mounted at `/streaming-2` while declaring
`subfolder: /streaming` hands the player a URL the proxy routes to the
container at `/streaming` instead, mid-session, with nothing written to
either log.

RomM refuses such an entry rather than resolve it. It still appears in the fleet
view, with a warning naming both values, and it cannot be claimed. The usual way
in is copying an entry for the second container and changing `host` but not
`subfolder`, which then falls back to its `/streaming` default.
</Callout>

### How RomM picks one

Entries for the same platform are one pool when they agree on `emulator`,
`memory_card_sync`, and protocol. Differing `subfolder` values do not split
them, which is the whole point: same origin pooling puts every container at a
path of its own.

When a player claims a container, RomM checks the pool in the order the
entries appear in `config.yml`, and gives them the first one nobody is
already holding. The rest follows from that:

- **One session per container.** Identity comes from `broker_host`, so a
  container serving three platforms still has a single slot. Claiming it for PS2
  takes it out of the GameCube pool as well.
- **A busy container is skipped quietly.** The second player to press play lands
  on the second container and never learns the first one was taken.
- **The 409 waits until every member is held.** That is RomM's way of saying
  no container is free, and it names the rom sitting on the container that
  would have been next.
- **The player already in a session gets that 409 too**, rather than a second
  container. Falling back to another container in the pool is only for
  players who missed out on the first one. A second session for the same user
  would be one nothing could reach, since status, release and save-and-exit
  all resolve to the first, and under whole-card sync the two halves would be
  mounting the same card.
- **Saves follow the player, not the container.** RomM keeps track of them by
  user, platform and emulator, and the broker clears the working slot before
  each launch, so landing on a different member next time changes nothing the
  player can see.

## What same origin costs you

Browsers send a site's cookies to every path under that site's own origin.
RomM's session cookie works the same way, so once the container lives at a
path under RomM's origin, that cookie is sent to the container on every
request for `/streaming/*` too. The container has no use for it and does not
read it, but it does cross the boundary. On a LAN deployment where the
container is already trusted enough to be handed the ROM library, this is not
a meaningful change. Don't point this setup at a container or network you
don't control.
