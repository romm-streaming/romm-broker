`retroarch_platforms.json` lists every RomM platform this repo supports and the
libretro core RetroArch uses to run it. (A libretro core is a plugin that lets
RetroArch emulate one specific system.) Most cores work as soon as you
download them. Some need a BIOS, firmware, or key file dropped into
RetroArch's system directory first, or the game just sits on a black screen
instead of booting.

This page is a summary specific to this repo, not a replacement for
libretro's own documentation. For anything not covered here, or for exact
file names and where to get them for each core, check libretro's
[core-specific BIOS documentation](https://docs.libretro.com/library/bios/#links-to-the-core-specific-bios-information),
the authoritative source this table was cross-referenced against.

Setup tiers used below:

- **Required**: the core will not boot a real game without this file in place.
- **Optional**: the core runs on a built-in HLE (High-Level Emulation)
  implementation instead of real firmware; a real file only improves accuracy
  or fixes specific titles.
- **None**: nothing to source for this platform.

A few rows are flagged because libretro's hub doesn't list this repo's exact
core name (sometimes the core is newer, or just named differently than what
the hub uses). Treat those as "check it yourself the first time you run into
that platform," not as settled fact.

| --- | --- | --- | --- |
| NES / Famicom | `mesen` | None | Cart dumps boot with nothing extra. |
| Famicom Disk System | `mesen` | Required | `disksys.rom` in the system dir. Only this platform needs it; plain NES/Famicom carts don't. |
| SNES / Super Famicom | `snes9x` | None | No BIOS concept for this core. |
| Nintendo 64 | `mupen64plus_next` | None | |
| Game Boy / Color | `gambatte` | Optional | A real boot ROM only changes splash timing; every game plays identically without one. |
| Game Boy Advance | `mgba` | Optional | `gba_bios.bin` fixes a handful of titles that rely on exact BIOS timing; HLE covers the rest. |
| Virtual Boy | `mednafen_vb` | None | |
| Nintendo DS | `melonds` | Optional | Real firmware plus `bios7.bin`/`bios9.bin` is recommended; the core falls back to a built-in HLE BIOS. |

## Nintendo, disc and 3D

| Platform | Core | Setup | Details |
| --- | --- | --- | --- |
| GameCube / Wii | `dolphin` | Optional | HLE boot by default; a real `IPL.bin` improves accuracy. Uses a custom save-subtree layout. |
| 3DS | `azahar` | Optional | Most dumps boot with nothing extra; encrypted `.3ds`/`.cci` files need decryption keys (`boot9.bin`/`boot11.bin`) in the system dir. This core comes from a GitHub release instead of libretro's usual build server (the buildbot), and it uses a custom save-subtree layout. This is the only way the broker supports 3DS: standalone Azahar has no IPC (a way for another program to send it commands), so there's no way for the broker to control it (see [Azahar setup](/docs/emulators/setup#azahar)). |

## Sony

| Platform | Core | Setup | Details |
| --- | --- | --- | --- |
| PlayStation | `swanstation` | Required | Region BIOS (e.g. `scph5501.bin`). This core isn't listed on libretro's hub under this exact name because it's a newer core based on DuckStation, but every PS1 core needs a real BIOS file. |
| PSP | `ppsspp` | None | The recommended way to run PSP games, better than the standalone PPSSPP module. PPSSPP emulates the PSP's firmware itself (the HLE from above), so there's no BIOS file to find. The broker automatically links the container's standalone PPSSPP asset tree (`/usr/share/ppsspp/assets`) into RetroArch's system directory, because the core won't boot without it. This only works if that package is included in your image. |

## Saves, states and imports

RetroArch sorts each core's files into a folder named for the core. The
folder takes the name the core reports about itself, which isn't always the
core's file name: the `dolphin` core reports `dolphin-emu`.

- In-game saves (SRAM) go in `saves/<core name>/<game>.srm`.
- Save states go in `states/<core name>/`.

The broker states these settings on every launch, so a setting in your own
`retroarch.cfg` can't move saves away from where every save archive already
keeps them. The platform table records each core's reported name as
`library_name`.

A [declared import](/docs/api/imports) can bring one `.srm` save into a
session only on a platform whose core loads one. The platform table records
this as `save_ram`, taken from a check of each core's source. These 23
platforms take one:

`nes`, `famicom`, `snes`, `sfam`, `n64`, `gb`, `gbc`, `gba`, `virtualboy`,
`genesis`, `sms`, `gamegear`, `sg1000`, `sega32`, `tg16`, `turbografx-cd`,
`supergrafx`, `neo-geo-cd`, `wonderswan`, `wonderswan-color`, `jaguar`,
`colecovision` and `psx`.

On `psx`, the `.srm` is the SwanStation core's first memory card. The core
loads it only while its `swanstation_MemoryCards_Card1Type` option stays at
the default, `Libretro`. The broker doesn't set core options, so an imported
save won't load if that option has been changed in RetroArch.

The other platforms refuse a `.srm`:

- **PSP**: the PPSSPP core keeps saves as SAVEDATA folders, not a `.srm`.
  The refusal names the standalone PPSSPP module instead.
- **GameCube, Wii and 3DS**: these cores keep saves in their own folder
  layouts, which imports don't place yet.
- **The rest**: the core keeps its save in a file of its own, or has none,
  so it would never read a `.srm`. The paths below are inside the core's
  `saves/` folder unless noted.

| Core (platforms) | Where the save is |
| --- | --- |
| `melonds` (nds) | `<game>.sav` |
| `flycast` (dc) | VMU files in the system folder, `dc/vmu_save_<port>.bin`, shared by every game |
| `fbneo` (arcade, cps1, cps2, cps3, neogeoaes, neogeomvs) | `fbneo/<driver>.fs` or `.nv`, named for the driver |
| `mednafen_ngp` (neo-geo-pocket, neo-geo-pocket-color) | `<game>.flash` |
| `handy` (lynx) | `<game>.eeprom` |
| `bluemsx` (msx, msx2) | `<game>.sram` |
| `opera` (3do) | `opera/per_game/<game>.0.srm` |
| `dosbox_pure` (dos) | `<game>.pure.zip` |
| `stella` (atari2600) | `stella/nvram/` |
| `yabasanshiro` (saturn) | `yabasanshiro/backup.bin`, shared by every game |
| `genesis_plus_gx` (segacd) | `scd_<region>.brm`, shared by every game of that region |
| `mesen` (fds) | `<game>.ips`, a patch against the disk |
| `puae`, `vice_x64`, `hatari` (amiga, c64, atari-st) | written into the disk image |
| `a5200`, `prosystem`, `freeintv`, `vecx`, `o2em`, `fuse` | no battery save |

The broker renames an imported save after the game being launched, whatever
it was called before. It refuses a `.sav`, `.rtc`, `.nv`, `.eep` or `.mpk`
file as needing conversion until each core's name for that file has been
checked. A save state isn't imported as a save: send it to
`PUT /api/session/state-file` after activate.
